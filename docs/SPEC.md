# Prompt2Prod — System Spec (contract between backend, agents and dashboard)

Prompt2Prod is an autonomous AI software crew on Google Cloud. A developer describes a change in plain
English (typed, spoken, or via REST/webhook). A multi-agent pipeline built with Google ADK + Gemini then
**plans → writes tests first → implements → runs tests & self-heals → reviews → builds (Cloud Build) →
deploys a live preview (tagged Cloud Run revision) → verifies the live preview with AI-generated smoke
tests → releases to production** (automatically in *Autopilot* mode, or after one-click human approval).
Every step streams live to the dashboard through Firestore.

### Stages (ordered) and agents

| key | label | agent (display) | what happens |
|---|---|---|---|
| `sandbox` | Sandbox | Orchestrator | isolated Cloud Run Job starts, repo restored from git bundle |
| `plan` | Plan | Planner | Gemini reads the repo, writes plan + acceptance criteria |
| `tests` | Tests first | Test Author | writes failing tests for the acceptance criteria (TDD) |
| `code` | Implement | Coder | edits files with tools (read/write/search) |
| `test` | Test & heal | Test Runner | runs pytest; on failure Coder fixes, up to 3 attempts |
| `review` | AI review | Reviewer | reviews the diff, quality score 0-100, risk level |
| `build` | Build | Builder | Cloud Build builds a container → Artifact Registry |
| `preview` | Preview | Deployer | new tagged Cloud Run revision, 0% traffic, unique preview URL |
| `verify` | Verify live | Verifier | AI-generated HTTP smoke tests against the live preview URL |
| `release` | Release | Release Manager | autopilot gate or human approval → 100% traffic |

Agents: `Orchestrator, Planner, Test Author, Coder, Test Runner, Reviewer, Builder, Deployer, Verifier, Release Manager`.

## REST API (Cloud Run service `prompt2prod`, base path `/api`)

Auth: write endpoints require `Authorization: Bearer <Firebase ID token>` (anonymous auth is fine).
Errors: JSON `{"detail": "message"}` with 4xx/5xx.

| Method & path | Body | Returns |
|---|---|---|
| `GET /api/config` | – | `{firebase:{apiKey,authDomain,projectId,appId,messagingSenderId,storageBucket}, projects:[project], limits:{perUserPerHour, perDay}, models:{planner,coder,reviewer}, version}` |
| `POST /api/tasks` | `{projectId, prompt, mode, source}` | `{id}` (201). 429 when rate-limited |
| `GET /api/tasks?limit=50` | – | `{tasks:[task without diff]}` |
| `GET /api/tasks/{id}` | – | task |
| `GET /api/tasks/{id}/events` | – | `{events:[...]}` |
| `POST /api/tasks/{id}/approve` | – | `{ok, release}` — promote preview to production |
| `POST /api/tasks/{id}/reject` | – | `{ok}` |
| `POST /api/tasks/{id}/rollback` | – | `{ok, release}` — restore previous production release |
| `POST /api/tasks/{id}/retry` | – | `{id}` new task with same prompt |
| `POST /api/tasks/{id}/cancel` | – | `{ok}` (queued tasks only) |
| `GET /api/metrics` | – | DORA metrics (same formulas as dashboard Insights) |
| `POST /api/projects/{id}/reset` | – | `{ok}` reset demo app to baseline |
| `POST /api/webhooks/intake` | `{prompt, projectId?, source?, requester?}` + header `X-Intake-Key` | `{id}` |

## Metrics formulas (DORA + productivity)
Over the last 14 days of tasks:
- **Deployment frequency** = deployed releases per day (count tasks with `release.promotedAt` per calendar day).
- **Lead time for changes** = `release.promotedAt − createdAt` (median, p90).
- **Change failure rate** = rolled_back / (deployed + rolled_back).
- **MTTR** = mean seconds between a release and the rollback that undid it (from project `releases`, `kind == rollback`).
- **Pipeline success rate** = (deployed + awaiting_approval + rolled_back) / finished tasks.
- **Tests written by AI** = Σ `tests.newTests`.  **Self-healed** = tasks with > 1 test attempt that ended green.
- **Engineer-hours saved** = Σ `plan.estimatedHours` over deployed tasks.
- **AI cost** = Σ `metrics.costUsd`; tokens = Σ (tokensIn + tokensOut).
